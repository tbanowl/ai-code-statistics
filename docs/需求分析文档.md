## 1. 项目概述

### 1.1 项目简介

Git-AI Metrics API 是一个基于 Flask 的 Web 应用系统，用于统计和分析 Git 仓库中 AI 生成代码的占比。系统通过接收 Git-AI 客户端上传的 Metrics 数据，进行多维度统计分析，并提供完整的 RESTful API 供前端调用。

### 1.2 技术栈

- **后端框架**: Flask
- **前端框架**: Vue 3
- **数据库**: SQLAlchemy ORM（支持 SQLite、PostgreSQL、MySQL）
- **任务调度**: APScheduler (BackgroundScheduler)
- **数据加密**: cryptography.fernet (SSH Key 加密存储)

## 2. 功能需求

### 2.1 统计查询 API (`/api/stats`)

#### 2.1.1 获取仓库列表

**端点**: `GET /api/stats/repositories`

**功能**: 获取所有仓库列表，支持分页和关键词搜索

**请求参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | int | 否 | 页码，默认 1 |
| page_size | int | 否 | 每页数量，默认 20，最大 100 |
| keyword | string | 否 | 搜索关键词 |

**响应示例**:
```json
{
  "success": true,
  "data": [
    {
      "id": "ctg3h1e...",
      "repo_path": "https://codeup.aliyun.com/org/repo.git",
      "repo_name": "repo",
      "created_at": 1711670400000
    }
  ],
  "pagination": {
    "total": 100,
    "page": 1,
    "page_size": 20
  }
}
```

### 2.2 仓库和 SSH Key 管理 API (`/api/stats-repo`)

#### 2.2.1 SSH Key 管理

**添加 SSH Key**
- 端点: `POST /api/stats-repo/ssh-key`
- 参数:
  - `key_name`: Key 名称
  - `public_key`: 公钥内容（可选）
  - `private_key`: 私钥内容

**列出所有 SSH Keys**
- 端点: `GET /api/stats-repo/ssh-keys`

**删除 SSH Key**
- 端点: `DELETE /api/stats-repo/ssh-key/<key_id>`

---

#### 2.2.2 仓库管理

**获取仓库 SSH 状态**
- 端点: `GET /api/stats-repo/<repo_id>/ssh-status`

**关联仓库 SSH Key**
- 端点: `PUT /api/stats-repo/<repo_id>/ssh-key`
- 参数: `ssh_key_id`（可设为 None 使用默认 Key）

**启用/禁用仓库统计**
- 端点: `PUT /api/stats-repo/<repo_id>/stats-flag`
- 参数: `repo_stats_flag` (0 或 1)

---

#### 2.2.3 归因统计查询

**仓库级归因统计**
- 端点: `GET /api/stats-repo/blame/repo/<repo_id>`
- 参数: `start_date`, `end_date`（可选）

**文件级归因统计**
- 端点: `GET /api/stats-repo/blame/file/<repo_id>`
- 参数: `stat_date`（可选）

**仓库贡献者归因统计**
- 端点: `GET /api/stats-repo/blame/repo/<repo_id>/contributors`
- 参数: `stat_date`（可选）

## 3. 定时任务

### 3.1 Metrics 事件处理任务

| 属性 | 值 |
|------|-----|
| 任务 ID | `metrics_event_processor` |
| Cron 表达式 | `*/2 * * * *` (每 2 分钟) |
| 功能 | 从原始数据表提取事件到各事件表 |
| 批处理大小 | 默认 100 (可配置) |

**处理流程**:
1. 查询 `extract=0` (未提取) 的原始记录
2. 标记为 `extract=2` (提取中)
3. 解析 JSON payload，分发到对应事件表
4. 失败事件记录到 `metrics_event_errors` 表
5. 标记为成功或失败 (`extract=1` 或 `extract=3`)

---

### 3.2 每日统计聚合任务

| 属性 | 值 |
|------|-----|
| 任务 ID | `daily_aggregation` |
| Cron 表达式 | `0 2 * * *` (每天 02:00) |
| 功能 | 从 Metrics 事件表聚合生成每日统计数据 |

**处理流程**:
1. 确定时间范围（默认为昨天）
2. 查询时间范围内的 Committed 事件
3. 按 仓库+贡献者维度聚合 AI 代码行数
4. 创建缺失的仓库和贡献者记录
5. 更新 `stats_daily_stats` 表

---

### 3.3 Git 代码归因统计任务

| 属性 | 值 |
|------|-----|
| 任务 ID | `git_blame_stats` |
| Cron 表达式 | `0 2 * * *` (每天 02:00) |
| 功能 | 统计仓库中 AI 代码归占比 |

**处理流程**:
1. 获取待统计的仓库列表（`repo_stats_flag=1`）
2. 为每个仓库克隆代码到临时目录
3. 使用 `git blame --line-porcelain` 分析每个文件
4. 从 notes 表查询 AI 归属信息
5. 计算仓库级、文件级、贡献者级统计
6. 保存到 `stats_blame_*` 表

---

### 3.4 任务清理任务

| 属性 | 值 |
|------|-----|
| 任务 ID | `task_cleanup` |
| Cron 表达式 | `0 3 * * *` (每天 03:00) |
| 功能 | 清理旧的任务执行记录 |
| 保留数量 | 最近 100 条 |

## 4. 数据库模型

### 4.1 Metrics 事件表

**原始事件表 (`metrics_events_raw`)**
- `id`: 主键
- `version`: 版本号
- `event_count`: 事件数量
- `payload_json`: 原始 JSON 数据
- `extract`: 提取状态 (0-未提取、1-成功、2-处理中、3-失败)
- `extract_fail`: 失败原因
- `received_at`: 接收时间
- `created_at`: 创建时间

**Committed 事件表 (`metrics_events_committed`)**
- 存储提交事件的详细信息（AI 代码行数等）

**Checkpoint 事件表 (`metrics_events_checkpoint`)**
- 存储检查点事件（文件级别）

**AgentUsage 事件表 (`metrics_events_agent_usage`)**
- 存储 AI Agent 使用事件

**InstallHooks 事件表 (`metrics_events_install_hooks`)**
- 存储钩子安装事件

**事件错误表 (`metrics_event_errors`)**
- 记录事件解析失败信息

---

### 4.2 CAS 对象表 (`cas_objects`)

- `hash`: 唯一哈希值
- `content_json`: 内容 JSON
- `metadata_json`: 元数据 JSON

---

### 4.3 统计表 (stats_*)

**仓库表 (`stats_repositories`)**
- `repo_path`: 仓库 URL
- `repo_name`: 仓库名称
- `repo_stats_flag`: 是否启用统计 (0/1)
- `ssh_key_id`: 关联的 SSH Key ID

**贡献者表 (`stats_contributors`)**
- `contributor_uid`: 贡献者唯一 ID
- `name`: 姓名
- `email`: 邮箱

**仓库贡献者关联表 (`stats_repo_contributors`)**
- 关联仓库和贡献者

**每日统计表 (`stats_daily_stats`)**
- `stat_date`: 统计日期
- `repo_id`: 仓库 ID
- `contributor_id`: 贡献者 ID
- `ai_generated_lines`: AI 生成行数
- `ai_accepted_lines`: AI 接受行数
- `human_lines`: 人工行数
- `ai_percentage`: AI 占比

---

### 4.4 任务执行表 (`task_executions`)

- `job_id`: 任务 ID
- `status`: 状态 (pending/running/completed/failed)
- `started_at`: 开始时间
- `finished_at`: 结束时间
- `execution_time_ms`: 执行时长
- `error_message`: 错误信息

---

### 4.5 遥测数据表 (`telemetry_envelope`)

- `envelope_data`: 遥测数据

---

### 4.6 Notes 表 (`authorship_notes`)

- `repo_url`: 仓库 URL
- `commit_sha`: 提交 SHA
- `note_blob_oid` / `original_commit_sha`: note blob ID
- `branch`: 分支
- `author_name`: 作者名称
- `author_email`: 作者邮箱
- `note_content`: note 内容

---

### 4.7 Git Blame 统计表 (stats_blame_*)

**SSH Key 表 (`stats_ssh_keys`)**
- `key_name`: Key 名称
- `public_key`: 公钥
- `private_key_encrypted`: 加密的私钥

**仓库级统计表 (`stats_blame_repo`)**
- `repo_id`: 仓库 ID
- `stat_date`: 统计日期
- `commit_sha`: 提交 SHA
- `branch`: 分支
- `total_lines`: 总行数
- `ai_lines`: AI 行数
- `non_ai_lines`: 非AI 行数
- `ai_ratio`: AI 占比
- `total_files`: 文件总数

**文件级统计表 (`stats_blame_file`)**
- `repo_id`: 仓库 ID
- `stat_date`: 统计日期
- `file_path`: 文件路径
- `total_lines`: 总行数
- `ai_lines`: AI 行数
- `non_ai_lines`: 非AI 行数
- `ai_ratio`: AI 占比

**仓库贡献者统计表 (`stats_blame_repo_contributor`)**
- `repo_id`: 仓库 ID
- `stat_date`: 统计日期
- `contributor_id`: 贡献者 ID
- `contributor_name`: 贡献者名称
- `contributor_email`: 贡献者邮箱
- `ai_lines`: AI 行数
- `non_ai_lines`: 非AI 行数
- `total_lines`: 总行数

**文件贡献者统计表 (`stats_blame_file_contributor`)**
- `file_id`: 文件 ID
- `stat_date`: 统计日期
- `repo_id`: 仓库 ID
- `file_path`: 文件路径
- `contributor_id`: 贡献者 ID
- `ai_lines`: AI 行数
- `non_ai_lines`: 非AI 行数
- `total_lines`: 总行数

## 5. 服务层

### 5.1 MetricsService

处理 Metrics 事件数据：
- 解析原始 JSON payload
- 识别事件类型（Committed、Checkpoint、AgentUsage、InstallHooks）
- 提取和转换字段值
- 保存到对应的事件表

---

### 5.2 CasService

CAS (Content Addressable Storage) 服务：
- 上传 CAS 对象（基于哈希存储）
- 读取 CAS 对象
- 验证哈希唯一性

---

### 5.3 OAuthService

OAuth 设备授权流程服务：
- 创建设备授权码
- 生成用户验证码 (XXXX-XXXX 格式)
- 交换令牌（access_token、refresh_token）
- 使用 JWT 生成令牌

### 5.4 NotesService

REST Notes Store 服务：

- 列出所有 notes

### 5.5 BlameStatsService

Git Blame 统计服务：

### 5.7 SshKeyService

- 获取仓库的 SSH Key

## 6. 调度器系统

### 6.1 任务注册机制

使用装饰器 `@scheduled` 声明任务：
```python
@scheduled(cron="0 2 * * *", job_id="daily_aggregation", name="每日统计聚合")
class DailyAggregationTask(BaseTask):
    def execute(self, context=None):
        ...
```

### 6.2 任务配置覆盖

```yaml
scheduler:
  jobs:
    daily_aggregation:
      cron: "0 10 * * *"
      enabled: false
```

### 6.3 任务执行

- 自动定时执行（根据 cron 表达式）
- 手动触发（通过 API）
- 记录执行历史和状态
- 支持超时检测和重试
- 并发安全检查
