  ---
  根本原因

  append_checkpoint 是一个无锁的 Read-Modify-Write 操作，本质上等价于：

  # 没有任何 flock / advisory lock 保护
  cat checkpoints.jsonl > tmp
  echo "$new_entry" >> tmp
  mv tmp checkpoints.jsonl

  修复方向：在 append_checkpoint 和 write_all_checkpoints
  中引入文件级的咨询锁（如 flock 或
  fs2::FileExt::lock_exclusive），或改用真正的原子追加（JSONL 格式本身支持
  append-only 写入，可以避免 read-modify-write 问题）。

  根本原因：daemon wait=false 与 pre-commit 快速路径的致命组合

  完整时序

  [PostToolHook] git-ai checkpoint claude --hook-input stdin
    → prepare_captured_checkpoint (只读文件，不写 checkpoints.jsonl)
    → send_control_request(wait=false)  ← 立即返回，AI checkpoint 进入 daemon

    ← hook 返回

  ... 用户执行 git commit ...

    → checkpoint::run(..., is_pre_commit=true)          # 本地执行，不经过

⏺ 代码一目了然，Windows 路径有三个根本性缺陷。

  三个独立的挂起根因

  根因 1：无信号传播机制（孤儿进程）

  Unix 路径（git_handlers.rs:60-90）有完整的信号转发机制：
  #[cfg(unix)]
  extern "C" fn forward_signal_handler(sig: libc::c_int) {
      let pgid = CHILD_PGID.load(Ordering::Relaxed);
      if pgid > 0 {
          unsafe { libc::kill(-pgid, sig); }  // 信号广播给整个进程组
      }
  }
  // SIGTERM / SIGINT / SIGHUP / SIGQUIT 都会被转发

  Windows 路径：#[cfg(windows)] 下完全没有对应实现。

  结果：
  Claude Code hook timeout → 杀死 git-ai.exe
  → Unix:  SIGTERM 通过 forward_signal_handler → 转发给子 git.exe →
  子进程组全部终止
  → Windows: git-ai.exe 被杀死，子 git.exe 变成孤儿，无人管理，在后台永远挂着

  这解释了"后台挂起不终止"——git.exe
  已经变成没有父进程的孤儿进程，永远存在于后台。

  ---
  根因 2：child.wait() 无超时

  Windows 路径（git_handlers.rs:984-1004）：

  #[cfg(not(unix))]
  match child {
      Ok(mut child) => {
          let status = child.wait();  // ← 无超时，永久阻塞
          ...
      }
  }

  Unix 路径虽然也用 child.wait()，但通过进程组 + 信号转发，Ctrl+C
  可以让子进程退出，从而让 wait() 返回。

  Windows 下如果 git.exe
  因为任何原因卡住（凭据提示、杀毒扫描、网络），git-ai.exe
  就和它一起死锁，永远等待。

  ---
  根因 3：CREATE_NO_WINDOW + 凭据提示死锁

  #[cfg(windows)]
  {
      if !is_interactive_terminal() {
          cmd.creation_flags(CREATE_NO_WINDOW);  // ← 在 hook 场景下必然触发
      }
  }

  Claude Code hook 调用时不是交互式终端 → is_interactive_terminal() = false → 子
   git.exe 带 CREATE_NO_WINDOW 启动。

  同时，proxy_to_git 没有设置 cmd.stdin(Stdio::null())，子进程继承 git-ai 的
  stdin。

  后果：
  git 需要凭据（push/pull/fetch）
  → 尝试在终端显示提示 → 没有窗口，无法显示
  → 尝试读 stdin 等待输入 → stdin 是 Claude Code 的 pipe，已经被 hook JSON
  消耗完了
  → git.exe 永远等待一个永远不会来的输入
  → git-ai.exe 在 child.wait() 里永远等待 git.exe

  ---
  触发路径总结

  Hook 场景（最常见）：
  git-ai checkpoint claude --hook-input stdin
  ├── 读取 stdin 的 hook JSON（stdin 被消耗）
  ├── 处理 checkpoint...
  │   └── 内部调用 git 子命令（git status / git diff 等）
  │       ├── CREATE_NO_WINDOW（因为不是交互式终端）
  │       ├── stdin 继承（已被消耗，EOF 或阻塞）
  │       └── child.wait()（无超时）
  │
  ├── 情况A: git.exe 等凭据 → 无窗口无法显示 → 阻塞 stdin → 双方永远挂起
  ├── 情况B: Claude Code 超时杀 git-ai → git.exe 成为孤儿在后台继续跑
  └── 情况C: 杀毒软件扫描 .git 目录 → git.exe 阻塞很久 → git-ai 跟着阻塞

  ---
  缓解方案（无需改代码）

  1. 最关键：禁止 git 等待凭据输入

  # 在系统环境变量中设置（永久生效）
  [System.Environment]::SetEnvironmentVariable("GIT_TERMINAL_PROMPT", "0",
  "User")
  [System.Environment]::SetEnvironmentVariable("GCM_INTERACTIVE", "never",
  "User")

  GIT_TERMINAL_PROMPT=0 会让 git 在无法获取凭据时直接报错退出，而不是永远等待。

  2. 预缓存凭据，让 git 不需要提示

  # 用 Windows Credential Manager 存储凭据
  git config --global credential.helper manager

  # 提前执行一次需要凭据的操作，让凭据缓存
  git fetch origin  # 在交互式终端里做，触发一次凭据输入和缓存

  此后 hook 里的 git 操作可以直接从 Credential Manager 读取，不需要交互提示。

  3. 如果用 SSH，设置非交互式 SSH

  # 使用 SSH agent，避免每次输入 passphrase
  [System.Environment]::SetEnvironmentVariable("GIT_SSH_COMMAND", "ssh -o 
  BatchMode=yes -o ConnectTimeout=10", "User")

  BatchMode=yes 让 SSH 在需要交互时直接失败，而不是等待。ConnectTimeout=10
  防止网络问题导致的无限等待。

  4. 定期清理孤儿 git.exe 进程

  # 查看所有 git 进程
  Get-Process git -ErrorAction SilentlyContinue | Select-Object Id, StartTime,
  CPU

  # 杀死所有挂起的 git 进程（谨慎使用）
  Get-Process git -ErrorAction SilentlyContinue | Where-Object {$_.CPU -lt 0.01}
   | Stop-Process

  或者写成定时任务，每隔几分钟清理一次运行时间超过 30 秒的 git 进程。

  5. 杀毒软件排除（减少 git.exe 被阻塞的概率）

  # 排除 git 本身
  Add-MpPreference -ExclusionProcess "git.exe"
  Add-MpPreference -ExclusionProcess "git-ai.exe"

  # 排除仓库目录
  Add-MpPreference -ExclusionPath "D:\your\repo\path"

  # 排除 git 安装目录
  Add-MpPreference -ExclusionPath "C:\Program Files\Git"
